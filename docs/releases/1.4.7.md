# 1.4.7 — reconstructed after the fact, because the bump rode inside a feature

**This receipt was written on 2026-09-14, after 1.4.8 was cut.** Every other file in this
directory was written when its release was cut. This one was not, and the reason is worth
recording: the version bump from 1.4.6 to 1.4.7 rode inside
[PR #444](https://github.com/atomchung/long-run-hybrid-coach/pull/444), an ordinary feature
pull request, rather than a cut of its own. No cut meant no receipt — and 1.4.7 is the
version production has been serving ever since.

Everything below is derived from git and from a live `/readyz` read, not from memory. What
a receipt normally also carries — which gates were run, what was verified on the day, what
the release meant in user terms — is not reconstructible and is not invented here.

## What to take from it

A version number lives in three files that a test holds equal, and nothing holds a version
number to a receipt. Cutting a release is therefore a deliberate act, and a bump that
arrives as a side effect of merging a feature produces a deployed version with no page
describing it. If a bump is needed, cut it.
