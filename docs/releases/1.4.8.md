**One PR moved the catalogue: #452.** It corrected two tool descriptions that said
something untrue — that a session focus excludes other sessions sharing its day, and that
held guidance is "unchanged" when nothing had verified it. The other seven left the

## The change worth reading

Every character budget in this repository lived in `tests/` — `MAX_CONTEXT_CHARACTERS`,
`FIELD_BUDGETS`, `READ_CEILINGS`, `FOCUSED_SESSION_DETAIL_CEILING`. Each asserted that a
committed fixture stayed under a line. None of them ran in production. An athlete whose
real data crossed the line was handed the oversized result anyway, and the client dropped
it: issue #233, 77,166 characters, a turn that could not happen.

`MAX_CLIENT_RESULT_CHARACTERS` is now enforced at runtime in `CoachGateway.route`,
measured on `len(json.dumps(...))` — the same string the MCP client receives, after the
envelope and `plan_state` are in. Not the context build, not the projection, not the
retained snapshot. The guard is deliberately **not** in `_text_content`, which serializes
every tool: refusing a confirmation the athlete already approved would be worse than
refusing a read. The refusal is built as an error and serialized afterwards, so it cannot
re-enter the guard.

The fixture budgets stay, as the early-warning signal they always were, and their comments
now name the runtime owner.

## Everything else

- **#278** — one Intervals error taxonomy across read and delivery. A 401 is reconnect
  whichever endpoint saw it; a 403 on optional evidence degrades without signing the
  athlete out; 429 keeps `Retry-After`; a malformed payload is not "no data". A 401 after
  a workout already reached Intervals keeps the delivery journal, and reconnect resumes
  **the same** approved set without a second calendar event.
- **#281** — the first plan's availability write converges on the exact confirmed retry,
  from a durable receipt. A later `recordAthleteAvailability` still wins. No second
  transaction framework; PlanState schema unchanged, `WRITER_CONTRACT_VERSION` still 6.
- **#315** — four DecisionEvent guards that ran on zero turns are gone, each invariant
  now with one live owner and a live-path test. The three producerless mode values stay
  in the enum on purpose: stored history carries `revisit_today`, and `doctor-store`
  revalidates the whole commit history.
- **#427's direction** — published schema fields now have recorded runtime dispositions,
  and prepare→apply conformance derives its echo set from the published schemas instead of
  a hand-written list.
- **Failure injection** — restart between preview and confirm, crash mid-commit, partial
  provider write and its four store fences, replay, wrong owner, stale version, corrupted
  hold, and the `publish_new_workouts: false` withdrawal path issue #410 said was never
  executed. It matches the contract.
- **Production truth** — `scripts/release_bundle.py observe` answers "what is live", dated.
  Issue bodies stopped carrying version numbers that go stale without an edit.


**`release_id` and `gateway_artifact_sha256` are bound to one exact commit.** Any later
commit -- including a change to this file -- produces different values. Staging a
`release_id` that does not match the commit being deployed makes the runtime preflight
refuse at startup, and on this deployment that refusal is an **outage** rather than a
rejection: the volume mounts to only one container, so the old one is stopped before the
new one starts, and a new one that will not start leaves nothing serving
(`docs/ops/roll-with-railway-cli.md`, observed 2026-08-18, ~26 minutes).

So re-derive at promotion rather than copying from here:

```bash
python3 scripts/release_bundle.py build \
  --gateway-domain https://mcp.paceandstaystrong.com \
  --git-commit <the full 40-character SHA being promoted> \
  --output <path outside this repository>
```

A receipt is a dated record, never current production.
