# 1.4.6 — a refusal now says which account it belonged to

Issue [#408](https://github.com/atomchung/long-run-hybrid-coach/issues/408) is where the
counters went; [PR #425](https://github.com/atomchung/long-run-hybrid-coach/pull/425) is
this. Priority: Current. Nothing an athlete does changes.

## Before → after, in user terms

| | 1.4.5 | 1.4.6 |
| --- | --- | --- |
| What an athlete does, anywhere | preview, one confirmation, apply | unchanged |
| Approvals in start → preview → apply | 2 | 2 |
| Pages, prompts, tools, schemas, annotations | — | unchanged |
| An access line on an authenticated request | `… access=authenticated tool=X outcome=Y` | `… access=authenticated owner=31657b3e62cdad2b tool=X outcome=Y` |
| An access line on an anonymous one | no account field | no account field |
| How long those lines last | whatever the platform keeps | plus an operator-held copy, if they run the puller |

## Why

`tool=` and `outcome=` say a call was refused. They cannot say whether six refusals on
one day were **one athlete six times** or **six athletes once**, and those are opposite
findings — the first is a defect in one path, the second is a defect everyone hits. That
distinction is what an onboarding question needs, and it was answerable until 1.4.3.

The registry counters answered it and were removed because they *wrote*: a platform
review counts a write as a state change, so seven reads and previews had to be annotated
as writes, which cost the athlete a third approval on an ordinary turn. The owner's
decision was that the report was not worth the permission.

A log line is not a write. So the marker rides there instead, and costs no approval, no
annotation, and no tool-catalogue change.

## What `owner=` is

The first sixteen characters of `binding(owner_id, key=token_hmac_key)` — the same keyed
handle the athlete's own export returns as `owner_reference`, documented in that schema
as the one identifier safe to quote publicly. A support mail quoting it and an operator
filtering these lines land on one account, and neither holds the owner id, the bearer, or
a provider athlete id.

Keyed to this deployment, so the same athlete under another deployment's key is a
different handle, a key rotation ends correlation across it exactly as it does for the
existing `client` handle, and a handle read out of the logs cannot be turned back into an
account without the registry.

Sixty-four bits is a trade, not a uniqueness guarantee: at a million accounts the chance
any two share a handle is about 3 in a hundred million. Enough for grouping one account's
requests inside one investigation; a service at a hundred times that scale should
lengthen the prefix rather than reason about the odds.

**What it does add is deliberate**: anyone holding the logs can now link one account's
requests across a day. That is the feature.

## Retention

`docs/ops/security-events.md` deferred a longer-lived sink until an investigation needed
one. That happened, so `scripts/archive_access_log.py` pulls the current window and
appends what the archive does not already hold. It is an operator tool on an operator's
machine — no deployment, no production change, nothing in the product reads it — and the
runbook now states that the resulting file outlives both the platform's retention and the
athlete's account, so it is the operator's to delete when the investigation closes.

The join is positional rather than by content, and that is not an implementation detail:
appending only lines "not already present" silently drops a repeat, and a repeat is the
finding. One athlete refused six times writes six lines differing only by a timestamp,
and a single 1,921-line production window pulled while writing this already held one pair
identical to the millisecond.

## Validation

2,728 tests pass on a clean tree, with two skips — both `root bypasses directory
permissions`, an environment limit of running the suite as root, unrelated to this change.
Repository safety passes for 317 candidate files.

Six regressions cover the marker: an authenticated line carrying sixteen hex characters
and none of the values it stands for; one account logging one handle across requests
while a second logs another; an anonymous request logging none, asserting first that the
anonymous lines it is about to check exist; the logged handle being a strict prefix of
the export's `owner_reference`; the construction pinned to the keyed binding, with the
same account under another key differing and a bare digest matching neither; and an empty
owner id resolving to no handle, so `access=` and `owner=` cannot disagree.

`tests/test_archive_access_log.py` holds the puller — ten cases, of which the two that
matter fail when content-set dedup is put back.

Two independent reviewers ran before merge, one cold-start Claude and one Codex. Both
found the dedup defect independently; the keyed-construction regression and the collision
wording exist because they asked for them.
