# 1.4.5 — deleting an account leaves the conversation

Issue [#417](https://github.com/atomchung/long-run-hybrid-coach/issues/417).
Priority: Current. 1.4.4 removed the token-shaped argument on the guess that it was what
ChatGPT's pre-dispatch checker reacted to. That release said in as many words that the
guess was unproven. It is no longer the product's bet: the two deletion tools are gone,
and a whole-account erasure is a written request the operator answers.

## Before → after, in user terms

| | 1.4.4 | 1.4.5 |
| --- | --- | --- |
| "Delete all my data" in any client | preview, one confirmation, apply | one answer: the support page, and a sentence saying nothing is submitted or deleted |
| What the coach reads first | the whole account, to compute the preview | nothing |
| Approvals the client asks for | one, sometimes refused at its own layer | none — no tool is called |
| Where the erasure runs | the gateway, if the client let the call through | an operator, against the scope the athlete confirmed by email |
| Tools in the catalogue | 24 | 22 |
| An older client that still calls `prepareOwnerDeletion` / `applyOwnerDeletion` | erased the account | refused, naming the same page, erasing nothing |
| Export, corrections, retractions, planning, delivery | unchanged | unchanged |

The support page is the fixed link the coach hands over:
`https://paceandstaystrong.com/support.html#data-by-email`.

## Why

A deletion the athlete confirmed and the product never heard about is the worst failure
this surface has. The model emits the call, the client's own approval layer refuses it
before it leaves the client, and nothing about that reaches the gateway — so the product
cannot complete the request and cannot say why. The athlete is left holding a preview and
their data, believing otherwise.

1.4.4 narrowed one plausible trigger. It did not, and could not, make the confirming call
reliable: whether a client dispatches an irreversible tool call is that client's decision,
measured per client, and this product neither sees it nor controls it. Keeping a route
whose last step is somebody else's veto, for the one operation that cannot be taken back,
buys convenience with a promise the product cannot keep.

So the promise moved to the route an operator can watch finish. The erasure itself did not
change: `owner_data.deletion_preview` and `owner_data.delete_owner` are the same functions,
fence and tombstone included, and `privacy-request-delete` is the command that was already
calling them.

## What the coach does now

Asked to delete everything, it reads nothing, calls nothing, and answers with the support
URL, that the page says what to email, and that nothing has been submitted and nothing
deleted. No preview, no second confirmation, no message sent on the athlete's behalf.

The URL reaches the model through `exportOwnerData`'s description rather than through the
served instructions, because a tool description is a channel every client delivers and
served instructions are not: claude.ai discards them and Claude Code truncates them. The
orchestration prompt carries the same sentence for the entries that do read it, and is
69 characters *shorter* than in 1.4.4 — the deletion paragraph it replaces was longer.

## What the operator keeps

Everything. `privacy-request-open`, `privacy-request-export`, `privacy-request-scope` and
`privacy-request-delete --confirm` are unchanged, and so is `delete-owner`. No customer
service tool, ticket queue or identity-verification system was added: the identity check
stays a person's judgement, recorded as `--identity-evidence`, exactly as the owner
decided on 2026-09-11.

## What moved, and what did not

- `tool_catalogue_sha256`: `1a6fa10574d066318a53110429dee132993ae26bf1c966a3d5372d581246ee42`
  → `405efcc6c6a138abb5032d1448f467eae7c5f3a22e5ae5a2d0642d696ed50759`. Two tools removed
  and one description changed: **Scan Tools must be re-run against production and a new
  plugin version submitted** (issue #182).
- `instructions_sha256`: `2f371af4f45dca097654bbdc9cd83890530d255a33a9b10f10d838b2738d732d`
  → `782e955970038afc718d44fac9ced9cee40225a7129d1c92c6a979020ecaff03`.
- The canonical Agent Skill: unchanged, and so is its digest. It never named the deletion
  tools.
- Submission packet: the two tools are gone from `tools`, the data-rights sentence of the
  description now says deletion is a written request and names the page, the reviewer's
  export-and-delete case is now an export and a deletion *request*, and the cross-account
  negative case no longer tells a reviewer to expect a deletion tool to exist.
- Annotations: no destructive tool remains in the catalogue at all.

## Rolling back

There is no stored shape either side of this, and nothing to migrate. A client that
cached the 1.4.4 catalogue keeps two names that now refuse; refreshing the tool list is
the whole of the client-side change, and a refusal erases nothing in the meantime.

## Validation

2,708 tests passed on a clean tree with no skip beyond the two the suite always skips;
repository safety passed for 314 candidate files.

What the new regressions hold:

- Both retired names, called over MCP, answer `status: blocked` with
  `error: account_deletion_moved`, carry the support URL, carry no `structuredContent`,
  and leave the owner directory byte-identical.
- The access line for one of those calls prints `tool=applyOwnerDeletion` and
  `outcome=blocked:account_deletion_moved`, and names neither the owner nor the bearer.
- `tools/list` serves 22 tools and neither deletion name.
- The erasure's own properties — every evidence group counted and removed, the identity
  rows, the credential that stops resolving, the racing write swept, the tombstone after
  the receipt, a cutover and an unfinished delivery both refusing — are asserted against
  `owner_data` directly, which is what the operator path calls.

The proposal-machinery tests that guarded the removed route are gone with it. What they
protected is the confirmed-scope digest, and `tests/test_privacy_request.py` already holds
it: a scope the requester never saw is refused, and so is one belonging to another account.

## Not proven here

That a real client hands over the page and opens it, and that none of them narrates a
deletion that did not happen, is measured on the clients after this rolls. So is
production `/readyz`. Neither is claimed by this suite or this document.
