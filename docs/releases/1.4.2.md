# 1.4.2 — open-by-default client admission

Owner decision: [#403](https://github.com/atomchung/long-run-hybrid-coach/issues/403).
Priority: Current. An unknown HTTPS client previously needed a Coach warning and browser
cookie; now every structurally valid, unblocked callback proceeds directly to Intervals
OAuth. The existing loopback exception remains. Trusted origins are metadata only.

The owner accepts that a malicious downstream client may hide its identity and induce an
athlete to complete Intervals OAuth, receiving a Coach bearer for that athlete. Downstream
identity disclosure belongs to the initiating client's UX. Registration alone grants no
authority and never enables cross-owner access. See [the threat model](../deploy-gateway.md#admitting-a-new-hosted-client).

Removed: Coach warning page, cookie binding, consent POST route, consent envelope and
consent-only event vocabulary. Retained: URL hardening, exact redirects, PKCE, public HTTPS
rules, audience binding, provider-token encapsulation, owner isolation, security-log privacy,
`/mcp` Origin validation and all #405 model surfaces. Blocked origins continue to refuse
registration and future authorization by already-issued client IDs; existing bearers are
not retroactively revoked by this origin list.

Validation: 2,644 tests passed with one skip; repository safety passed. HTTP regressions
cover unknown HTTPS registration → direct authorization → fake-provider callback → token
redemption → MCP, plus two-owner isolation, registration without authority, block checks,
ambiguous URL variants and absence of the removed route. The fake-provider receipt is not
a real-provider authorization receipt. No ChatGPT/Claude/Gemini/OpenClaw UI acceptance or
OpenAI submission is implied. Recorded [1.4.1 receipts](1.4.1.md) remain unchanged.
